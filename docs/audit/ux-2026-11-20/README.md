## Топ-5 проблем и минимальные правки

### 1. Первое занятие заставляет уходить из формы и искать её снова — STAFF, `/staff/schedule`

Путь «с нуля»: форма занятия открывается **под** сеткой, далеко от нажатой ячейки ([02](02-staff-lesson-form-1280.jpg)). Преподавателя и аудиторию из формы создать нельзя — только ссылка «Добавьте связь в справочнике… затем вернитесь сюда» ([03](03-staff-no-teacher-1280.jpg)). «Вернуться к расписанию» ведёт к фильтрам, а не к форме. После каждого сохранения (преподаватель, «готовое занятие», публикация) страница прыгает к справочнику ([05](05-staff-after-publish-jump-1280.jpg)) — вероятно, из-за оставшегося в адресе `#schedule-resources`. Созданное «готовое занятие» не выбирается автоматически.

Правка без изменения API/схемы: «Вернуться к расписанию» → якорь формы занятия; после сохранения убирать hash и прокручивать к форме; автовыбор только что созданного готового занятия; маленькие встроенные формы «+ преподаватель» / «+ аудитория» рядом с пустыми списками (те же существующие API).

### 2. Конфликты обнаруживаются по одному и непонятным языком — STAFF

Еженедельная серия дважды упала на конфликте с seed-занятием 19.11, каждый раз показан только один ([04](04-staff-conflict-1280.jpg)): «Конфликт: группа Демо-группа 1 занят(а) 2026-11-19 с 08:30 до 09:50». ISO-дата, «занят(а)», нет подсказки, какое время свободно, нет варианта «пропустить эту дату».

Правка: формат даты `19.11.2026 (чт)`, нормальная формулировка; если сервер уже возвращает список — показать все конфликты списком. Пропуск даты — отдельное продуктовое решение.

### 3. Иерархия действий: несколько одинаковых основных кнопок на экране

На `/staff/schedule` одновременно четыре кнопки «Проверить изменения» одного вида; на `/staff/grades` четыре основные кнопки подряд («Показать студентов», «Открыть результаты», «Применить период», «Выставить результат») ([07](07-staff-grades-1280.jpg)). Вторичные действия (`Добавить исключение`, `Создать дисциплину`) того же веса и вплотную к основным — это и есть замечание «кнопки слишком близко». Предпросмотр для добавления преподавателя/аудитории показывает «изменяемых занятий: 0… атомарно» — лишний шаг с жаргоном.

Правка (CSS + подписи): один primary на форму, остальные `secondary`/ссылки; отступ между группами кнопок ≥ 16 px; уникальные подписи («Проверить семестр», «Проверить размещение»); для справочника — сохранение без предпросмотра занятий, если API это допускает, иначе хотя бы скрыть строку про занятия.

### 4. Фильтры занимают первый экран, а главное — ниже

Студент: на «Оценках» и «Заявках» при 390 px весь первый экран — фильтр периода/статуса, сам средний балл и список ниже ([09](09-student-grades-390.jpg), [10](10-student-applications-390.jpg)). Сотрудник: на 1280×800 сетка расписания начинается ниже сгиба ([12](12-staff-filters-1280.jpg)); после перезагрузки семестр/факультет/направление сбрасываются, хотя семестр один ([06](06-staff-schedule-390.jpg)).

Правка: фильтры свернуть в `<details>` «Фильтры» с краткой сводкой; результаты первыми. Для STAFF — автоподстановка единственного семестра и запоминание последнего выбора (localStorage или query), без изменений сервера.

### 5. Мелкий текст, сжатые заголовки, разнобой подписей

Нижнее меню студента 11.2 px, кнопки «День/Неделя», «Выйти» 12 px, «К сегодняшнему дню» ещё мельче ([08](08-student-week-390.jpg)). Заголовки блоков («Создать семестр», «Поступившие обращения», имя студента в оценках) почти не отличаются от текста и прилипают к полям. В сетке STAFF даты без дня недели ([01](01-staff-grid-1280.jpg)), «Вне учебных дней» выглядит как кнопка. Меню на телефоне «Пары/Студенты», на компьютере «Расписание/Прикрепления»; бейджи разделов разнородны («ДЕКАНАТ / 01», «УЧЁБА», «ДЕКАНАТ / ЗАЯВКИ» у студента); имя «Демо Студент 1» и «Студент 1 Демо». Кнопка «Выйти» на desktop STAFF плавает поверх контента. Активная вкладка «Преподаватели/Аудитории» не выделена.

Правка в токенах/общих стилях: минимум 13–14 px для подписей и кнопок, отступ под заголовком блока, день недели в сетке, единые подписи навигации, нормальный (не плавающий) «Выйти», `aria-pressed`/активный стиль вкладок.

## Прочие находки

- `/applications/<не-UUID>` (например, `/applications/new`) показывает «Сервис временно недоступен» с HTTP 200 вместо «Заявка не найдена» ([11](11-student-bad-link-360.jpg)); в логе `campus.operation_failed UNEXPECTED`. Серверная правка, отдельно от дизайна.
- Доступность: у ряда полей нет связанной подписи — `select` объявляется по выбранному значению, чекбоксы групп/дисциплин как «on», поле названия семестра без имени. Нужна связь `label`↔поле.
- Успешные действия подтверждаются мелким «Сохранено.» или никак (создание семестра, преподавателя); стоит единый заметный статус.
- После создания дисциплины поле с названием не очищается — риск повторного нажатия.
- В dev-логе предупреждение `pg`: «client.query() when the client is already executing a query is deprecated» — не UX, но сломается на pg@9.
