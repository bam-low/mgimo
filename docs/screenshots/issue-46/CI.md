## Совместимость новой 404 с Functions

Первый Node CI на `0cb1c63` прошёл standalone, но в локальном Functions-наборе новый public E2E получил 500 вместо 404. Причина — тестовый маршрутизатор читал dynamic rewrites, но игнорировал сгенерированный конечный маршрут 404. Добавлен выбор этого маршрута из настоящего Build Output config и передача его служебного error-context неизменённому Next handler; статус/HTML не подделываются. Заголовки конечного error rewrite больше не применяются ко всем успешным маршрутам. Проверка по-прежнему требует 404, русскую H1 и рабочий переход, не исключена ни из одного runtime.

Новый официальный Functions build, artifact gate четырёх Node24 functions и целевой public E2E — PASS. Полный Functions и удалённые CI фиксируются в описании PR по результату. Это проверка локального harness, не реального hosted ingress. Auth-лимиты, workflow, runtime security gates и production NO-GO прежние.
