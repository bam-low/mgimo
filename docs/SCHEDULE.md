# Учебная структура и расписание — Feature 1, Issue #29

Утверждённый scope: [Issue #29](https://github.com/bam-low/mgimo/issues/29), [Tracker #25](https://github.com/bam-low/mgimo/issues/25). PR #28 вручную merged владельцем 06.11.2026, merge commit `c6d4e2707f049d5142e340d323274dd07ec965fe`; только после проверки GitHub merge создана ветка `feature/schedule-issue-29` от этого main. Это функциональная вертикаль, не новый foundation и не готовый полный MVP.

## Готовые сценарии

- STAFF: `/staff/structure` — создать факультет, направление и группу своего вуза; переименовать, деактивировать/активировать. Вложенная структура и история сохраняются. Деактивация с подтверждением закрывает учебный доступ всей ветки без изменения membership/EnrollmentRequest истории.
- STAFF: `/staff/schedule` — выбрать группу и неделю, создать занятие, изменить дисциплину/время/место/преподавателя, отменить, восстановить при отсутствии пересечения либо убрать из расписания с подтверждением. Есть ошибки, состояние выполнения и подтверждённый результат.
- STUDENT: `/today` — все занятия университетского дня, текущее занятие и живой прогресс, до пар/перемена/после пар/нет пар. `/schedule` — отдельный день или полная неделя с навигацией и пустыми днями. Отмены явно отмечены.
- Профиль/прикрепления сохранены в `/cabinet` и `/staff`; общая ролевая навигация ведёт только к настоящим реализованным разделам. После перевода новый запрос читает новую группу; после отзыва или деактивации ветки расписание закрыто. PENDING/REJECTED сохраняют доступ к минимальному профилю.

## ASSUMPTION — минимальные обратимые решения

Точные повторения/академические периоды в исходных источниках OPEN, поэтому занятие имеет **конкретную дату**, а не неявное недельное повторение. Семь дней — понедельник–воскресенье. Дисциплина пока текстовый title занятия; отдельный справочник Subject не вводится без вертикали успеваемости. Преподаватель и аудитория — необязательный вымышленный текст, не новые User/роли/доступы.

Формы принимают один локальный день и начало/конец в IANA зоне вуза; конец строго позже начала, граница интервала `[start,end)`. Следующая пара может начинаться точно в момент конца предыдущей. Для одной группы два SCHEDULED занятия не пересекаются; отменённые не резервируют время. Сложные межгрупповые ограничения преподавателей/аудиторий и ночные/многодневные занятия здесь не вводятся. Невозможное или неоднозначное локальное время DST отклоняется, а не угадывается. Поддерживаемый диапазон формы 2000–2100; демо-вуз Europe/Moscow.

Родитель созданной структуры не меняется редактированием: перенос групп/направлений между ветками мог бы неявно изменить исторический контекст. В этой вертикали управление — создание, переименование и обратимая деактивация. В учебной структуре действие «Убрать в архив» открывает подтверждение, после чего запись видна в отдельном архиве. Чтобы вернуть вложенную запись, сначала восстановите её родителя. Восстановление родителя сохраняет собственные статусы его дочерних записей. Удаление занятия — tombstone `DELETED`, исключённый из списков; запись и audit остаются, физического DELETE у runtime нет. Отмена `CANCELLED` видна студенту и может быть восстановлена отдельным подтверждённым действием. Финальные токены, SVG и шрифтовые файлы не объявлены утверждёнными.

## Данные, сервер и транзакции

Additive migration `20261106180000_schedule`: Faculty/Program получают active и version; StudentGroup — version. Новая ScheduleEntry: groupId, title, teacher/room, startsAt/endsAt TIMESTAMPTZ, status SCHEDULED/CANCELLED/DELETED, optimistic version, timestamps. БД проверяет положительный интервал и допустимый статус; индекс groupId+startsAt. Никаких Grade/Application/Notification моделей, расширений PostgreSQL или разрушительных миграций.

`POST /api/staff/structure`, `POST /api/staff/schedule`: same-origin, bounded JSON, strict Zod, APPROVED STAFF своего вуза, per-user rate limit. Scope берётся из текущей серверной сессии. Транзакционный advisory lock по университету сериализует записи структуры, расписания и проверку группы при регистрации/подтверждении/переводе. Lock transaction-scoped совместим с pooled transactions; University остаётся SELECT-only, лишний UPDATE grant на неё не требуется. Проверки STAFF/активности повторяются в транзакции. В текущем маленьком MVP сериализация записей одного вуза — осознанный trade-off; чтение не удерживает этот lock после запроса.

Пересечение проверяется после lock перед записью; конфликт и stale version безопасно дают 409. CREATE структуры содержит UUID operationId, уникальный id неизменяемого audit event: повтор не создаёт вторую ветку даже при потере ответа. Audit и изменения коммитятся вместе; ошибка audit откатывает запись. EnrollmentRequest статусы, авторизация и A31/A32 не перерабатывались: добавлена проверка effective active всей иерархии и согласованный lock.

`GET /api/schedule?view=today|week&day=YYYY-MM-DD`: серверная текущая группа STUDENT+APPROVED+active membership/group/parents, либо STAFF-selected group только своего вуза. Подставленный groupId не даёт студенту чужой доступ. DTO содержит только занятие/группу/зону/границы дня и serverNow; private/no-store, без Actor/auth/Session. Чтение ограничено одним днём/неделей и 500 занятиями: превышение явно отклоняется, не обрезается молча.

Точная SQL policy расширена только для реализованных функций: Faculty/Program/StudentGroup/ScheduleEntry — SELECT/INSERT/UPDATE, без DELETE/TRUNCATE/DDL/TEMP/grant option; University SELECT, AuditLog SELECT/INSERT без мутаций. Контекстные роли и ownership проверяются приложением, новая RLS или глобальная роль не вводилась. Grant/check после миграции и настоящие limited-role HTTP negatives обязательны; прежняя read-only structure policy больше не подходит этой версии приложения.

Публичная synthetic-only регистрация показывает активную структуру исключительно `demo-university`, включая новые STAFF-created демо-группы. Сервер проверяет полную цепочку по БД; роль/identity поля остаются запрещены. Это не разрешение настоящих identity данных или публичного создания вузов. Никакие настоящие ФИО преподавателей/названия учреждений вводить не следует.

## Часы, обновление и приватность

Университетский день выводится через Intl/IANA, абсолютные моменты не смещаются локальной зоной браузера. Живой счётчик использует serverNow и прошедшее монотонное browser performance время; системные часы устройства не определяют выбранную пару. Перерисовка каждую секунду, загрузка свежего расписания/прав каждые 30 секунд и при возвращении в окно; при смене университетского дня загружается новый день без reload. Новые HTTP-запросы сразу учитывают перевод/отзыв; polling не обещает мгновенно стереть уже доставленный HTML.

При hidden/focus revalidation приватный список очищается, запрос отменяется/заменяется; ответ старого поколения не восстанавливает чужой контекст. 401/403/сеть очищают данные и показывают безопасное сообщение/повтор/профиль. Списки не хранятся в browser storage или shared cache. Прогресс имеет native progress и текстовый процент/остаток; фокус не захватывается ежесекундно, reduced motion соблюдён.

## Демо и ручная приёмка

Seed сохраняет прежние три учётки и независимые private passwords без сброса прав. Две группы получают разные вымышленные дисциплины, преподавателей, аудитории, три пары с промежутками в каждый будний день недели первого seed. На выходных пар нет. Повтор не переносит занятия на новую неделю и не восстанавливает изменённые/отменённые/DELETED записи; сотрудник меняет даты через настоящий интерфейс. Seed по-прежнему отвергает неготовую базовую структуру вместо скрытого ремонта. Пароли не выводятся.

1. На отдельной synthetic DB выполнить migrations, grant/check и seed с тремя private паролями; повтор seed должен пройти, ничего не сбросив.
2. STAFF создаёт факультет → направление → группу. Создаёт занятие на сегодня в зоне вуза; отдельную пару на другом дне недели. Совпадающий интервал другой пары этой группы должен дать понятную ошибку; соседний допустим.
3. STAFF штатной формой переводит студента в новую группу с причиной. Студент открывает «Главная», затем «Расписание»/«Неделя»: дисциплина, времена, преподаватель/место соответствуют этой группе. Второй студент другой группы занятия не видит, прямой чужой groupId даёт 403.
4. Проверить реальное начало/конец/перемену, движение прогресса без refresh, день устройства в другой зоне, смену суток в зоне вуза. На 360/390px текст/действия без горизонтального overflow; desktop сотрудника с доступными формами.
5. STAFF меняет занятие и отменяет; студент получает обновление при focus или в течение poll. Восстановление проверяет конфликты. Удаление с подтверждением убирает занятие из списков, запись/audit остаются.
6. Деактивировать группу/направление/факультет: новый GET студента запрещён, история не удалена. Реактивация возвращает effective access при сохранённых действующих правах. Отзыв прикрепления по A31 закрывает доступ независимо от активной структуры.
