## Доступность

Утверждённые требования handoff: активность не только цветом; время текстом; прогресс с текстовым эквивалентом; заметный клавиатурный фокус; масштабирование текста, читаемые контрасты и reduced motion. Целевой стандарт и числовые пороги контраста/размеров/масштабирования ещё не зафиксированы. Они не объявляются выполненными без проверки.

Предлагаемый способ проверки: пройти все согласованные действия клавиатурой, проверить порядок/видимость фокуса и доступные имена; увеличить текст и проверить отсутствие потери содержания; включить reduced motion и убедиться в доступности прогресса без обязательной анимации. Точная степень масштабирования и измеримые пороги должны быть согласованы до приёмки UI. Компонентные детали — в COMPONENTS.

## Будущая приёмка UI — не выполнена в Issue #5

- Сопоставить главную на 390 с выбранной концепцией № 1 переданной доски. Для заявления пиксельного совпадения нужен отдельно утверждённый точный source-макет, которого пока нет.
- Проверить на 360 отсутствие горизонтального скролла страницы, видимость времени/занятий и достижимость всех продуктовых разделов. Длинные названия и списки не скрывают основной смысл.
- Проверить все сегодняшние пары, активность и прогресс по реальному времени в зоне вуза: до пар, текущая пара, перемена, окончание, пустой день. Вне диапазона не должно быть фальшивой активности; зона устройства не подменяет зону вуза.
- Проверить общие компоненты и идентичность студента/сотрудника, включая клавиатуру, фокус, текстовые состояния и reduced motion.
- После согласования широких layouts проверить те же сценарии на утверждённых ширинах.

Эти проверки относятся к отдельному Issue на реализацию. Сейчас приложения нет: UI-код и Playwright не создаются/не запускаются; выполняются только проверки документации.

### Предложенные правила для утверждения

- Student: при недостатке ширины складывать вторичные блоки после сегодняшнего расписания, а не скрывать часть занятий; никакой фиктивной grade/request summary, пока нет модулей/данных. Боковая навигация desktop может стать компактной навигацией с достижимыми реальными разделами; число/группировка/иконки/высота/точка перехода OPEN.
- Staff: при недостатке места предложить читаемый список дней/занятий вместо плотной недельной сетки; inspector — связанная inline-панель или доступный drawer после owner review. Это **PROPOSED**, мобильного Figma-эталона нет. Сохранить выбранную группу/неделю/контекст редактирования и возврат focus; не превращать раскладку в новый сценарий.
- Если будущая сетка имеет внутренний scroll, он должен быть локализован/обозначен и иметь доступную альтернативу. Горизонтальный overflow всей страницы недопустим. Окончательный pattern не утверждён.
- Длинные названия/ошибки/русские строки/масштаб текста не должны убирать время, статус или действия; числа и пары дат не заменять нечитаемой обрезкой. Никогда не исправлять слетевшую типографику случайными absolute/margin с сохранением только одной ширины.

### Доступность и будущая проверка

Текстовый эквивалент прогресса/времени, заметный focus, keyboard, контраст и reduced motion остаются обязательными. PROPOSED цель — WCAG 2.2 AA, конкретные semantic пары/пороги и target scale требуют принятия, не являются автоматически APPROVED. Измеренные пары известных HEX — в TOKENS; они не доказывают доступность нового интерфейса.

Будущая UI-Issue должна проверить 360/390/1280 screenshots обеих реально реализуемых ролей, промежуточные ширины по содержанию, staff list/grid/inspector после выбора pattern, отсутствие page overflow, клавиатурный цикл и возврат focus, labels/errors/busy/conflict, масштабирование/длинную кириллицу, reduced motion. Время: exact start/end, до/перемена/идёт/после/нет пар, midnight, внешняя browser timezone; прогресс действительно обновляется без reload. Права/данные: own group, перевод/отзыв/неактивная иерархия/session/User, не менять server guards ради визуальной сверки.

**В Issue #31 UI snapshots/Playwright/layout tests не выполняются и не заявляются PASS.** Проверяются документация/источники/целостность assets; приложение/CI-конфигурация не меняются. Figma pixel-perfect text gate отложен до исправленных font assets и exports.
