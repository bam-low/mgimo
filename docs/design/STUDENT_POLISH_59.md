## Границы решений

Владелец отдельно разрешил использовать прежнюю иллюстрацию либо сделать новую. Создан самостоятельный локальный `public/design/campus-watercolor.png`: image_gen,16.11.2026, исходное описание неоклассической университетской архитектуры/акварели/бордовой листвы и действующей палитры. Это вымышленное здание, не фотография конкретного вуза, не логотип и не вырезка из DOCX. Next Image поставляет адаптивный размер. Существующий знак/wordmark сохранён. Новый логотип ожидается отдельно. Необязательная иллюстрация книг не извлекается из растра.

Сохраняются Literata/Onest, бордовый/кремовый/lavender Academic Editorial2.0, реальные состояния и пятираздельная мобильная навигация. На360/390 сначала учебный день и расписание, потом сервисы. На768 страницы не превращаются в сжатую desktop-sidebar. На1280 шапка занимает собственную строку, действия не лежат поверх greeting. Краткое обозначение конкурсного концепта/вымышленных данных есть; форма демонстрационных справок и её маркировка не меняются.

Факультет/направление берутся из уже авторизованной иерархии active enrollment, без нового API/запросов чужого контекста. При отсутствии прикрепления профиль честно сообщает, что структура станет доступна после подтверждения; новое чтение чужой группы не добавляется. История профиля — существующий EnrollmentRequest; заявки/справки доступны по действующему разделу, не реализованы повторно. В карточках только настоящие Grade/Application, без среднего балла/фиктивных результатов.

Запрещённые этим scope темы из DOCX не кодировались: Subject/связи преподавателей/правила среднего балла и ведомостей, фото/storage, сервер/БД/миграции/API/security/seed/production data. Допустимое изменение входа явно утверждено Issue; это page routing, не изменение auth/session/лимитов/ролей.

## Проверка качества и честные ограничения

Съёмка — production Next.js, настоящий Chromium, новая локальная PostgreSQL *_test и вымышленные seed records. Исходная main отдельно собрана из immutable git archive54ec540 с генерацией Prisma и runtime gate; feature build из отдельной ветки. Никакого VPS/существующей БД/изменения host clock. Для разных состояний дня из настоящего защищённого HTTP200 берутся занятия, затем только в Playwright управляется response clock/empty UI fixture. Это проверка отображения, не доказательство смены серверного времени; фактические пустые даты и API отмены отдельно проверяет прежний E2E.

Камера ждёт SSR/workspace/реальных lesson rows, шрифты и видимые изображения. Скрытые lazy images не блокируют съёмку. Кадры «Загрузка…» пересняты и не выдаются за готовый экран. Кадр после прокрутки создаётся только когда есть действительная прокрутка; дубликаты не размножаются. Матрица/PNG hashes фиксируют фактическое покрытие. Desktop empty/grades используют реальные пустые данные; статусы заявок могут отличаться от нарисованного референса.

Выполнены последовательные визуальные итерации по настоящим кадрам: устранены excess whitespace mobile landing, слишком высокий date toolbar/обрезанная дата, скрытый текст completed, двойные отступы шапки, статусная окраска доступа и лишнее повторение даты/предупреждений. На реальных кадрах также выявлен старый low-contrast hover невыбранного segmented button: исправлен scoped hover, E2E измеряет его contrast≥4.5 и высоту≥44px после завершения CSS transition. Активный режим выделен бордовым/белым как в DOCX, включая hover, вместо слабой светлой тени. Контрольные ширины360/390/768/1280, клавиатурная активация CTA/focus, min44px для основных кнопок. Отдельная QA-метрика проверяет пересечение masthead-actions с greeting/heading и горизонтальное переполнение.

Локально20unit/79PostgreSQL integration/18E2E и дополнительный focused schedule-states PASS, lint/typecheck/build/runtime gate. Первый E2E17PASS/1FAIL был старым селектором текста группы: заменён на точное значение/видимость семантического поля. Ошибочный повтор всей suite вместо focused упёрся в штатный registration quota; лимиты/RateBucket не менялись. Корректная focused команда — `npx --no-install playwright test tests/e2e/schedule-states.spec.ts`, без npm-аргументов после составного `&&` script. Следующие CI выполняют весь набор на чистой БД.

VPS historical A287912fe сохраняет старый UI: E2E явно проверяет его прежний `/cabinet`, четыре week links и прежнее состояние текста. Candidate/standalone/Functions проверяют новый `/today`, один переход/next marker и читаемые завершённые пары. Ничего не skip/disable: все18 прежних сценариев остаются в обоих VPS наборах. Это разные версионные UI-контракты, права/реальный HTTP guard проверяются как прежде.

Пиксельное совпадение не заявляется: у референса другая иллюстрация, настоящие данные/высота текста/неделя различаются, mobile адаптирован отдельно. Physical Android/iOS/Safari/screenreader/полный WCAG не подтверждены этими Chromium-кадрами. Визуальная приёмка владельца обязательна. Точный HEAD, результаты трёх CI и ссылки публикуются в Draft PR после терминальных checks.
