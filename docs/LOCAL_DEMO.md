# Локальное демо для этапа 6.5

Только вымышленные сведения и специально маркированные документы. Production NO-GO. Эти команды не развёртывают приложение на VPS. Основной путь — Bash, Node 24.x/npm 11.x, Docker с PostgreSQL 17; macOS/Windows требуют соответствующей оболочки и отдельной проверки. Результат чистого прогона фиксируется ниже после проверки, а не предполагается.

## Подготовка с нуля

Установите Git, Docker и Node версии из `.nvmrc`. Убедитесь, что Docker работает, а порты 3000 и 55433 свободны. В отдельном каталоге:

```bash
git clone https://github.com/bam-low/mgimo.git
cd mgimo
# Для ревью до merge сначала переключитесь на HEAD Draft PR этапа 6.
node --version
npm --version
docker version
node scripts/local-demo.mjs init
```

Последняя команда создаёт **приватные**, исключённые из Git `.env.local` и `.local-demo/postgres.env` с независимыми случайными секретами. Существующий `.env.local` не перезаписывается. Не публикуйте файлы, вывод с паролями, cookie, дампы или скриншоты входа с заполненным паролем. Просматривайте собственные реквизиты локально в редакторе. Логины: `student1@example.test`, `student2@example.test`, `staff@example.test`; пароли — соответствующие `DEMO_STUDENT1_PASSWORD`, `DEMO_STUDENT2_PASSWORD`, `DEMO_STAFF_PASSWORD` в вашем `.env.local`.

PostgreSQL хранит все данные, включая файлы, в постоянном именованном volume. Контейнер доступен только на loopback:

```bash
docker volume create campus-local-demo-data
docker run -d --name campus-local-demo \
  --label campus.local-demo=campus_local_demo \
  --env-file .local-demo/postgres.env \
  -p 127.0.0.1:55433:5432 \
  -v campus-local-demo-data:/var/lib/postgresql/data \
  postgres:17-bookworm@sha256:839fbb5a4942a7758dd93e18b42ea5649807491a0545b5eeeb8f0b8bb11857a5
docker exec campus-local-demo pg_isready -U campus_demo -d campus_local_demo
```

Дождитесь `accepting connections`; не запускайте миграции раньше. Это отдельная локальная demo-БД с owner-ролью для миграций/seed; не используйте её роли/привилегии для публичного runtime. Публичные runtime сохраняют [строгую DB policy](../scripts/launch-db-policy.mjs).

```bash
npm ci --ignore-scripts
node --env-file=.env.local node_modules/prisma/build/index.js generate
node --env-file=.env.local node_modules/prisma/build/index.js migrate deploy
node --env-file=.env.local prisma/seed.mjs
node --env-file=.env.local prisma/seed.mjs
node node_modules/next/dist/bin/next dev --hostname 127.0.0.1
```

Откройте `http://localhost:3000`. Next автоматически читает `.env.local`; CLI/seed должны получать env явно, как выше. `.env.example` описывает переменные; не заменяйте случайные секреты пустыми/публичными значениями. Если используете свой PostgreSQL, URL-encode специальные символы пользователя/пароля через `encodeURIComponent`, не передавайте URL в чат или shell history. Не устанавливайте trusted-IP header для локального прямого доступа. На публичном ingress он обязателен и должен перезаписываться прокси.

Seed создаёт два разных одобренных студенческих membership, сотрудника, вымышленную учебную структуру/занятия и две исходные заявки Student 1. Повтор проверяет реквизиты и не сбрасывает пароли, права, статусы и историю. Готовый файл не публикуется seed: сотрудник должен реально загрузить образец из [demo/documents](../demo/documents/README.md).

## Ручной сценарий

1. Войдите Student 1 → «Заявки». Создайте обычное обращение с вымышленным текстом и отдельно справку с вымышленной целью. После отправки откройте карточку; запишите её адрес локально. Повторная отправка одного operationId не создаёт дубликат.
2. В отдельном приватном окне войдите STAFF → «Заявки». Проверьте фильтры типа/статуса/даты и карточку. Примите обычное обращение в работу, оставьте комментарий, завершите с ответом без вложения. Student 1 видит ответ и историю.
3. Откройте справку, примите в работу. Выберите «Выполнить»: кнопка запрещена до сохранения документа; сервер также отвергает такой запрос 409. Сначала попробуйте файл с неподдерживаемым содержимым: форма сохраняет выбор/текст ошибки, прежнее состояние заявки не меняется.
4. Загрузите `demo/documents/demo-certificate.pdf` (или JPG/PNG). Визуально проверьте каждый лист: «Образец / Не является официальным документом», только вымысел, без настоящих подписей/печатей. Подтвердите это checkbox. Дождитесь именно **сохранения сервером**, а не только 100% передачи. Проверьте файл по защищённой ссылке сотрудника, затем выполните заявку с ответом.
5. Student 1 обновляет карточку и скачивает справку. PDF передаётся attachment, открывается системным просмотрщиком. Сравните SHA256 скачанного PDF и исходного образца (`sha256sum` в Linux, `shasum -a 256` в macOS или `Get-FileHash` в PowerShell). Для JPEG/PNG сравнивать исходный hash нельзя: сервер декодирует и нормализует изображение с удалением метаданных; сверяйте SHA256 сохранённой версии из защищённого API карточки.
6. STAFF заменяет выполненную справку с причиной минимум 10 символов. Проверьте две версии и прежние байты по истории; студент получает только новую. Статус остаётся «Выполнена».
7. В другом приватном окне Student 2 не видит чужую заявку, прямые адреса карточки/API/скачивания не дают чужих данных. Проверьте мобильные ширины 360 и 390 px, навигацию, форму и скачивание; desktop 1280 px. Это не заменяет ваш собственный UX-аудит и проверку реальных устройств.
8. Остановите Node (`Ctrl+C`), снова запустите. Справка, история и версии должны сохраниться в БД. Никаких внешних storage/VPS для сценария не требуется.

Production standalone проверяется отдельно от dev:

```bash
# Сначала остановите dev.
npm run build
HOSTNAME=127.0.0.1 node --env-file=.env.local .next/standalone/server.js
```

## Остановка, backup и восстановление

`Ctrl+C` останавливает приложение. `docker stop campus-local-demo` останавливает БД, сохраняя volume. Для продолжения: `docker start campus-local-demo`, дождитесь pg_isready, затем запустите приложение. Не удаляйте volume при обычной остановке.

Остановите запись приложения перед контрольным backup; дамп содержит пароли-хеши, сессии и все вымышленные файлы, поэтому храните его приватно вне Git:

```bash
umask 077
docker exec campus-local-demo pg_dump -U campus_demo -d campus_local_demo -Fc > .local-demo/backup.dump
docker exec campus-local-demo createdb -U campus_demo campus_local_demo_restore
docker exec -i campus-local-demo pg_restore -U campus_demo -d campus_local_demo_restore --exit-on-error < .local-demo/backup.dump
```

Восстановление выполняется в **новую** пустую БД, исходная не перезаписывается. Сделайте приватную копию `.env.local`, заменив только последний сегмент DATABASE_URL на `campus_local_demo_restore`; сохраните оригинальные BETTER_AUTH_SECRET и demo credentials. Запустите standalone с этим env-file. Повторите вход Student 1/STAFF, скачивание PDF, hash-проверку, историю двух версий, ответ/события и проверку Student 2. После проверки остановите Node и вернитесь к исходному env-file. Дамп сохраняет BYTEA/versions/events/audit; обычный backup не должен исключать новые таблицы. Удалять восстановленную БД можно только после проверки её точного локального имени, никогда по произвольному production URL.

## Разрушительный сброс только локального демо

Сначала остановите приложение и сделайте backup, если история нужна. Следующая команда **безвозвратно удалит все данные только `campus_local_demo`**: заявки, файлы всех версий, аудит, сессии, оценки, расписание и пользователей. Она требует точное подтверждение имени, отдельный demo-контейнер/label, проверяет приватный localhost URL и не использует произвольный DATABASE_URL для удаления:

```bash
node scripts/local-demo.mjs reset --confirm campus_local_demo --app-stopped
node --env-file=.env.local node_modules/prisma/build/index.js migrate deploy
node --env-file=.env.local prisma/seed.mjs
```

Секреты приложения и demo-пароли ротируются, PostgreSQL password/volume остаются. После нового seed используйте новые реквизиты из приватного env. Никакого `docker volume prune`, сброса всей машины, удаления чужих БД или расширения runtime DELETE privileges. Для другого имени/удалённой БД reset отказывает.

## Диагностика

- Занят порт: остановите известный локальный процесс либо согласованно измените порт и private DATABASE_URL; не останавливайте неизвестные контейнеры.
- PostgreSQL не готов: проверьте pg_isready и имя контейнера. Ошибка миграции — сначала правильный env-file, существующая БД и credentials, затем `migrate status`; не редактируйте применённые миграции.
- Seed отказал: исходные реквизиты/структура не соответствуют БД. Он намеренно не восстанавливает отозванные права и не меняет пароли. Возьмите исходный private env либо явно сбросьте только локальное демо.
- 401: войдите заново. 403: проверьте membership/роль/активное прикрепление; перевод сохраняет историю, отзыв закрывает учебные действия и скачивание.
- 409: обновите карточку с сохранением ввода; проверьте актуальный статус/version/current document и квоты всех версий. Не нажимайте повторно вслепую после потери сети.
- 413/415/400 при загрузке: размер, расширение/MIME и структура; PDF до 10 страниц без активных элементов/шифрования, статичный JPG/PNG до 12 Мп. Нет автоматического OCR/очистки настоящих ПД: используйте исключительно подготовленный вымышленный образец.
- 429: дождитесь окончания окна лимита; не очищайте RateBucket и не меняйте IP/права ради обхода. Лимиты описаны в [APPLICATIONS.md](APPLICATIONS.md).

## Свидетельство воспроизводимости

Проверено 13.11.2026 в Linux Debian GNU/Linux 13 x86_64, Node 24.22.1/npm 11.9.0, Docker/PostgreSQL 17 и Chromium. Использован отдельный чистый экспорт исходников без node_modules/.next/private env, собственная установка `npm ci --ignore-scripts`, новая PostgreSQL/volume и новые приватные реквизиты, без общих скрытых env. macOS и Windows не объявляются проверенными.

Фактически пройдены generate → все семь миграций → seed дважды → dev и настоящий сценарий двух ролей → production build/standalone → повторный вход и сравнение обоих файлов после перезапуска Node → pg_dump/restore в новую БД → остановка/запуск PostgreSQL с сохранением volume → повторное защищённое скачивание с совпадающими SHA256, версиями и событиями; Student 2 получает 404 на чужую карточку/файл. Затем выполнен guarded reset только исходной demo-БД, проверена смена всех пяти реквизитов, миграции/seed повторены и весь сценарий снова пройден на новых реквизитах. Восстановленная БД reset не затрагивается.

[Реальные снимки 360/390/1280 px](screenshots/issue43/README.md) получены из production standalone закрытого локального HTTPS-стенда после проверки русского выбора файла, native form feedback, сохранения ввода при превышении размера и настоящего file chooser. Результаты CI/трёх runtime на точном HEAD приводятся в Draft PR; эта локальная проверка не означает production GO или завершённый UX-аудит владельцем.
