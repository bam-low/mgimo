## Сценарии

STAFF: «Расписание» → «Учебные семестры»: произвольные название, начало/конец, опорный понедельник числителя, одиночные исключения и диапазоны с пояснением. Ручной ввод ДД.ММ.ГГГГ и календарь; API использует строгий ISO. Календарь показывает четыре недели и переход к любой дате, числитель/знаменатель и исключения. У полей нет фиксированного учебного года или длительности. Границы включительны; опорный понедельник может предшествовать началу. Чередование от опоры, а не ISO week; каникулы не сдвигают его. Дублирующиеся исключения применяются один раз. Диапазон, выходящий за границы, отклоняется с требованием уточнить его; автоматического усечения нет.

Семестр принадлежит вузу. Нормализованный дубликат названия явно отклоняется. Пересекающиеся семестры разрешены с предупреждением в предпросмотре; выбор семестра при создании расписания всегда явный.

«Конструктор»: выбрать семестр, факультет → существующее направление и дату; режим «Все группы направления» или «Одна группа». Desktop сравнивает группы по столбцам. Mobile показывает дни и переключение групп; широкая таблица не увеличивает ширину страницы. Все даты семестра доступны через дату/недельные переходы. Прежние занятия и другие семестры видны в том же интервале с отметкой, поскольку они резервируют ресурсы.

Добавление: выбрать группы, Subject, необязательные Teacher/Room, время и EVERY / A / B / ONCE. Несколько групп одного направления означают одну общую лекцию. Предпросмотр показывает конкретные даты, затронутые записи, число исключённых занятий и предупреждения. Несколько разных занятий в один исключённый день считаются отдельно; пересечения исключений не удваивают одно занятие. Сохранение требует отдельного подтверждения. Ошибка сохраняет поля и operationId. Неназначенный ресурс явно обозначен: его занятость проверить нельзя.

Выбор карточки открывает редактирование одного занятия для всех связанных групп либо всех будущих повторений с выбранной даты. Отделение одной группы — отдельное явное действие, создающее независимое занятие и проверяющее его конфликт с оставшейся лекцией. Для одного занятия доступны отмена, восстановление с повторной проверкой и tombstone-удаление. Общая лекция не дублируется и не конфликтует сама с собой.

«Преподаватели и аудитории»: создание/редактирование/деактивация/реактивация. Преподаватель имеет несколько связей с Subject, без User/аккаунта. Аудитория уникальна по нормализованным корпусу и номеру внутри вуза. Численность, вместимость и occupancy отсутствуют. Subject используется из успеваемости; его управление остаётся в `/staff/grades`. Структура Faculty → Program → StudentGroup прежняя, доступна ссылка `/staff/structure`.

## Модель и миграция

Additive `20261111000000_semester_builder`:

| Модель | Назначение |
| --- | --- |
| Semester | universityId, name/nameKey, start/end/anchor DATE, exclusions JSON, version |
| Teacher / TeacherSubject | Вузовский преподаватель и активные связи с дисциплинами |
| Room | Вузовские корпус/номер, нормализованный уникальный ключ, active/version |
| ScheduleTemplate / TemplateGroup | Правило, периодизированные segments JSON, активные группы, version |
| ScheduleEntry | Прежний объект конкретного занятия; добавлены typed refs, semesterId/templateId, slotDay, generation, manual, sourceEntryId |
| ScheduleGroup | Несколько активных связей одного конкретного занятия с группами |

Составные FK Semester/Subject/Teacher/Room/Template + universityId запрещают чужие typed references. Группа проверяется сервером по полной иерархии. CHECK сохраняют допустимые статусы/положительные интервалы, проверяют календарные границы, понедельник и тип правила. Runtime получает только SELECT/INSERT/UPDATE новых таблиц, без DELETE/TRUNCATE/DDL/TEMP/grant option. Политика точного состава таблиц и восстановление backup обновлены; immutable audit trigger не меняется.

Миграция не переписывает исходные занятия: их groupId, текстовые teacher/room/title, timestamps и история остаются. Одинаковые старые строки не сопоставляются автоматически с Teacher/Room. Старое занятие читается через groupId, новое через ScheduleGroup. Сохраняется один якорный groupId для совместимости. Legacy API проверяет и новые групповые связи, но отказывается изменять typed занятия: UI даёт рабочую ссылку в конструктор. Текстовые старые преподаватели/аудитории не имеют надёжной идентичности, поэтому глобальная проверка этих ресурсов возможна только для явных typed ссылок.

Датированные поля title/teacher/room сохраняют снимок подписей при публикации/редактировании; справочник не переписывает историю названий. Subject FK общий с Grade, но семестр расписания не становится периодом оценки. Старый issuedOn оценок остаётся 2000–2100; новые семестры не наследуют это ограничение.

## История и безопасные изменения

Каждое правило хранит периоды действия: изменение «с даты» сохраняет ранний период, заменяет последующие. Это необходимо и при последующей регенерации из-за настройки календаря. Шаблон не переносится между семестрами/направлениями изменением идентификаторов.

Регенерация сохраняет прошедшие и уже начавшиеся занятия, а также все ручные изменения, отмены и удаления. Неизменённые будущие записи получают tombstone; новые поколения материализуются атомарно. slotDay сохраняет исходное место ручного занятия даже после переноса, предотвращая его повторное создание. Отделённое занятие ссылается на источник. Аудит содержит before/after и изменение групп/ресурсов/статуса; физического удаления истории нет.

**Утверждено владельцем в чате:** если новые границы/исключения делают активное ручное будущее занятие недопустимым, блокировать настройку семестра, пока сотрудник явно не перенесёт или не отменит его. Автоматического удаления/переноса нет. Ручные отмены не возрождаются после снятия исключения. Изменение только названия/пояснений или эквивалентного объединения исключений не регенерирует занятия.

## API и безопасность

`GET /api/staff/schedule/builder` — scoped справочники и структура. С `semesterId`, `programId`, `from`, необязательным `groupId` — недельный список и шаблоны. Только актуальный APPROVED STAFF; DTO не загружает студентов/учётки/сессии. Превышение технических размеров явно даёт 413, не тихое усечение.

`POST /api/staff/schedule/builder` принимает строгий `{command, preview, token?, confirmed?}`:

- SEMESTER_CREATE(operationId,calendar) / SEMESTER_EDIT(id,version,calendar).
- TEACHER_CREATE(operationId,name,subjectIds) / TEACHER_EDIT(id,version,name,active,subjectIds).
- ROOM_CREATE(operationId,building,number) / ROOM_EDIT(id,version,building,number,active).
- TEMPLATE_CREATE(operationId,semesterId,programId,rule) / TEMPLATE_FUTURE(id,version,from,rule).
- OCCURRENCE_EDIT(id,version,day,startTime,endTime,subjectId,teacherId,roomId).
- OCCURRENCE_CANCEL / OCCURRENCE_RESTORE / OCCURRENCE_DELETE(id,version).
- DETACH(id,version,operationId,groupId,day,startTime,endTime,subjectId,teacherId,roomId).

preview=true выполняет проверки без записи. При commit нужны полученный token и confirmed=true. SHA256 привязывает подтверждение к команде, версиям и плану; он не является полномочием. Сервер заново перечитывает права/ссылки и проверяет конфликты после university advisory lock в той же транзакции, что запись/аудит. Другой сотрудник, отозванные права, stale version, повтор operationId или новый конфликт не обходятся старым preview. Повтор создания даёт 409 без дублей. После неопределённого сетевого исхода следует обновить данные перед повтором.

Для всех создаваемых дат запрещены пересечения `[start,end)` по группе, typed Teacher и typed Room в рамках всего вуза. Совпадение Subject не конфликт. CANCELLED/DELETED ничего не резервируют; восстановление проверяется заново. Редактирование отменённого занятия тоже проверяет университет всех ресурсов и обновляет их подписи; неактивные собственные ресурсы допустимы в отменённой истории, но восстановление требует действующих ресурсов и назначения дисциплины. Неполная публикация невозможна; ошибка аудита откатывает также шаблон/связи. Все записи расписания и структуры используют один университетский lock, включая прежний API.

Сохраняются same-origin, JSON ≤16 KiB, строгий Zod, текущие серверные сессии/CSP/guards, private/no-store. Write preview/commit вместе ограничены 60 запросами/минуту на сотрудника; чтение конструктора — 180. Student GET/today/week/live progress работают через прежний DTO, собственную актуальную группу и активную цепочку. Списки не раскрывают другие группы студента, ресурсы других вузов или auth данные.

Технические пределы отделены от ввода календаря: 1000 конкретных дат на правило, 1000 изменяемых занятий и 5000 связей групп на публикацию; 100 периодов правил/шаблонов в массовой настройке; история/конфликтная выборка ≤10000; недельное чтение ≤500. Календарь принимает реальные четырёхзначные ISO годы 0001–9999, не фиксированный академический год. Слишком большой материализуемый batch отклоняется явно; ИИ/solver/автоматического разбиения на частичные транзакции нет.
