# Заявки и демонстрационные справки

Источник согласованных решений: [Issue #43](https://github.com/bam-low/mgimo/issues/43), последняя секция утверждения Q1–Q8 владельцем от 12.11.2026. Исторические пометки PROPOSED не отменяют это утверждение. Production NO-GO сохраняется.

## Пользовательский контракт

`Application` отделена от `EnrollmentRequest`: последняя управляет прикреплением к группе. Заявка принадлежит `UniversityMembership`, содержит снимок группы при подаче и сохраняется после перевода.

Два типа: `GENERAL_REQUEST` (тема 3–120, содержание 10–3000 символов) и `STUDY_CERTIFICATE` (вымышленная цель 3–300, необязательное пояснение до 1000). Исходное обращение после отправки не редактируется. Студент не отменяет и не переоткрывает заявку.

Переходы: `SUBMITTED → IN_PROGRESS → COMPLETED | REJECTED`; допустим ранний `SUBMITTED → REJECTED`. Комментарии доступны только в работе. Ответ при выполнении — 1–4000 символов; мотивированный отказ — 10–2000. Справка завершается только после транзакционного сохранения действительного документа. Обычное обращение завершается без файла.

STUDENT с APPROVED membership и единственным действующим прикреплением к активной учебной структуре читает только собственные заявки. Отзыв прикрепления закрывает чтение, создание и скачивание. STAFF своего университета сохраняет доступ к истории; при закрытом учебном доступе заявителя может только мотивированно отказать в открытой заявке. Другие изменения запрещены до восстановления доступа.

## Файлы

Настоящие байты хранятся в PostgreSQL BYTEA, без внешнего storage и публичных URL. PDF/JPEG/PNG до 3 МиБ включительно; максимум пять неизменяемых версий. Квоты — 30 МиБ на membership и 300 МиБ на университет, сумма **всех сохранённых версий**. Удаление старых версий и увеличение runtime DELETE privileges не предусмотрены.

Multipart принимает один файл и один JSON metadata до 4 КиБ, общий поток до 3 МиБ + 64 КиБ. Поток ограничен по объёму и времени; одновременно валидируются максимум два файла на процесс. На ingress только точный маршрут загрузки получает увеличенный body limit; общие JSON-маршруты сохраняют 16 КиБ и прежние auth/security gates.

Проверяются расширение, MIME, сигнатура и реальная структура. PDF: до 10 страниц; запрещены шифрование, JavaScript/actions, вложенные файлы, формы и непустые аннотации. Статичные JPEG/PNG декодируются и нормализуются с удалением метаданных, до 12 Мп и 10000 пикселей по стороне. Проверка выполняется в отдельном Worker с ограничением JS heap и таймаутом; это не антивирус и не автоматическое распознавание ПД. Нативная память декодера дополнительно ограничивается лимитами процесса/контейнера, лимитом пикселей и параллелизма.

Сотрудник обязан визуально проверить каждый лист и подтвердить вымышленность, маркировку «Образец / Не является официальным документом», отсутствие настоящих подписей/печатей. Подтверждение фиксируется в аудите. Автоматическое OCR, нанесение водяного знака, генерация PDF, электронная подпись и inline PDF preview не реализуются.

Замена требует причины 10–500 символов, версии заявки и ожидаемого currentDocumentId. Новые байты, revision, событие, аудит и атомарная смена указателя сохраняются одной транзакцией. Ошибка сохраняет прежний документ и статус. Замена у COMPLETED оставляет статус COMPLETED. STUDENT скачивает только текущую версию выполненной справки; STAFF — историю своего университета. Проверка прав выполняется при каждом скачивании, с аудитом авторизации выдачи (не ложным утверждением получения файла пользователем).

Ответ — attachment с серверным именем, `private, no-store`, `nosniff`, same-origin resource policy и CSP sandbox. Проверка membership, учебного доступа и действующей серверной сессии выполняется до выдачи байтов. Не помещать названия исходных файлов, содержимое, пароли и cookie в логи.

## БД и конкурентность

Добавлены Application, ApplicationDocument и ApplicationEvent. Миграция аддитивная, существующие учебные записи сохраняются. Составные FK ограничивают связи одним университетом/заявкой; SQL CHECK защищают статусы, обязательный файл выполненной справки, длины, размеры и revision. Триггеры запрещают UPDATE/DELETE документов и событий, runtime получает для них только SELECT/INSERT. Application получает SELECT/INSERT/UPDATE.

Операция имеет UUID, служащий идентификатором события; повтор отклоняется 409. optimistic version и ожидаемый указатель защищают устаревшие формы. Блокировки membership → university → application согласованы с переводом/отзывом. Университетская advisory lock сериализует проверку общих квот. Сессия проверяется внутри транзакции. Ошибка аудита откатывает всё действие.

Лимиты: создание 5/10 минут и максимум 10 открытых заявок; изменения 60/минуту; загрузка 6/10 минут на сотрудника; скачивание 60/минуту. Quota учитывает сохранённые байты, включая заменённые. Не сбрасывать счётчики для обхода ограничений.

## API и интерфейс

- STUDENT: GET/POST `/api/applications`, GET `/api/applications/:id`, GET `/api/applications/:id/document`.
- STAFF: GET `/api/staff/applications`, GET `/api/staff/applications/:id`, POST `/api/staff/applications/:id/actions`, POST `/api/staff/applications/:id/documents`, GET `/api/staff/applications/:id/documents/:documentId/content`.
- Списки: тип/статус, для STAFF даты в timezone университета, cursor pagination по 25. История событий пагинируется; документные DTO содержат только метаданные, никогда BYTEA.
- Изменения требуют same-origin, строгое Zod тело, серверную сессию и роль/университет/ownership. Произвольный membershipId из клиента не принимается.
- Страницы `/applications` и `/staff/applications`: реальные формы, фильтры, история и загрузка с прогрессом; при ошибке ввод и выбранный файл сохраняются. 409 предлагает обновить данные перед повтором.

ApplicationEvent содержит стабильные eventId, schemaVersion, actor и сведения о публичном изменении; получатель определяется через membership заявки. Notification/Outbox, отправка уведомлений и интерфейс уведомлений относятся к этапу 7 после локального UX-аудита 6.5.
