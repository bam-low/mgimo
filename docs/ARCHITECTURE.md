# Предлагаемая архитектура

**Статус: предложение, не утверждено.** Утверждённые ограничения взяты из [PRD](PRD.md), решения и вопросы — в [DECISIONS](DECISIONS.md). Этот документ не является разрешением на реализацию или установку зависимостей.

## Предварительный стек

Next.js, React, TypeScript, Tailwind CSS, PostgreSQL, Prisma, Playwright. Выбор каждого инструмента, совместимые версии, среда исполнения, менеджер пакетов и площадка размещения требуют согласования. Предлагается одно веб-приложение с двумя интерфейсами, серверной бизнес-логикой и реляционной БД. Конкретный способ API, сессий и развёртывания пока не выбран.

## Сущности и связи — предложение

| Сущность | Связи и назначение |
| --- | --- |
| Вуз | Имеет факультеты и часовой пояс IANA; в демо только один вымышленный вуз. |
| Факультет | Принадлежит вузу, содержит направления. |
| Направление | Принадлежит факультету, содержит группы. |
| Группа | Принадлежит направлению; связана со студентами и занятиями расписания. |
| Пользователь | Связан с вузом, имеет роль студента или сотрудника. Для студента предлагается связь с одной группой; правила смены группы требуют решения. |
| Занятие расписания | Принадлежит группе; содержит время, дату/правило повторения и сведения о занятии, точный формат ещё не выбран. |
| Оценка/зачёт | Принадлежит студенту, относится к учебной дисциплине; шкалы, периоды и модель дисциплины требуют решения. |
| Заявка | Принадлежит студенту; имеет тип, статус и сведения об обработке сотрудником. Каталог и переходы не утверждены. |
| Уведомление | Имеет получателя; предлагаются текст, время и отметка прочтения. Триггеры и каналы требуют решения. |

Цепочка: вуз → факультет → направление → группа → занятия. Пользователь-студент → группа → занятия. **Расписание в запись студента не копируется** — это утверждённое требование. Предлагается проверять на сервере согласованность всей цепочки выбора. Наличие сущности вуза учитывает развитие модели, но не означает реализацию multi-tenant SaaS.

## Модель доступа

Утверждено: проверка прав на сервере, хеширование паролей и безопасное хранение секретов. Скрытия кнопок недостаточно.

Предлагаемые границы доступа:

- Неавторизованный пользователь имеет доступ только к согласованным сценариям регистрации/входа.
- Студент читает свой профиль, оценки/зачёты, заявки и уведомления; создаёт свои заявки и читает расписание своей группы.
- Сотрудник управляет структурой и расписанием демонстрационного вуза, обрабатывает заявки. Способ предоставления роли сотрудника требует согласования; самоназначение через регистрацию не допускается в предлагаемой модели.
- Сервер получает пользователя из проверенной сессии и проверяет роль, принадлежность объекта и разрешённый переход статуса при каждом запросе. Идентификатор из клиента не считается доказательством доступа.

Редактирование успеваемости сотрудником, восстановление паролей и точные права на профиль не утверждены. Предлагаются безопасные серверные сессии и защита операций изменения данных от подделки запросов; конкретные механизмы и алгоритм хеширования выбираются отдельно. Секреты не хранятся в Git или клиентском коде. Демо-аккаунты не отменяют разграничения доступа.

## Время и часовой пояс

Утверждено: главная использует реальное время и часовой пояс университета. Сам часовой пояс ещё не задан; нельзя молча подставлять часовой пояс браузера или хоста.

Предлагается хранить IANA-зону у вуза; конкретные моменты времени — в UTC, вычисление дня и показ — в зоне вуза. Для локальных повторяющихся занятий понадобится отдельно согласованная модель дат, повторений, исключений и переходов часового пояса.

Предлагаемое правило интервала пары: начало включительно, конец исключительно. До первой пары — «до пар», между парами — «перемена», после последней — «все пары закончились», при пустом дне — «сегодня пар нет». На главной остаются все пары дня; активная выделяется и обновляется при смене состояния. Позднейшее утверждённое дизайн-требование Issue #5 / Handoff v1: прогресс текущей пары обязателен, в диапазоне 0–100%, с текстовым эквивалентом (см. [DESIGN](DESIGN.md)); визуальные размеры этим не задаются. Правила пересечений занятий, частота обновления и источник синхронизации часов остаются открытыми.

## Размещение и проверяемость

Доступность из РФ без VPN, включая все ресурсы, обязательна. Предлагается минимизировать внешние зависимости загрузки и рассмотреть локальную поставку шрифтов/изображений с проверкой лицензий; способ хостинга не выбран. Доступность подтверждается проверкой из РФ, а не предположением по названию провайдера.

Для будущего кода предлагаются проверки модели прав, связей данных и временных границ, а также сценарии двух студентов и сотрудника в браузере. Playwright предварителен; инструментальные решения требуют согласования. В Issue #1 тестовый код и инфраструктура не создаются.
