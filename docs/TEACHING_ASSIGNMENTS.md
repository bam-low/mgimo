# Дисциплины и группы — Issue #62

Реализация для ручного ревью по [Issue #62](https://github.com/bam-low/mgimo/issues/62), от main `d5db6844`. Не считать принятой main до ручного merge. [Живые скриншоты и матрица](screenshots/issue-62/README.md). VPS не изменялся, Production NO-GO сохраняется, известный security blocker — [#64](https://github.com/bam-low/mgimo/issues/64).

## Сценарий сотрудника

1. «Расписание» → «Дисциплины и группы»: выбрать факультет и направление. Выбрать существующий Subject или создать по названию через тот же справочник успеваемости.
2. Лекция: явно выбрать группы и одного связанного с дисциплиной преподавателя. Семинары: явно выбрать группы, назначить преподавателя каждой; массовое назначение можно уточнить по отдельным строкам. Сначала проверить, затем подтвердить настройку. Это ещё не публикация расписания.
3. «Конструктор»: семестр, направление, режим всех групп либо одной группы. Дата просмотра и правило повторения независимы. Дни до начала/после окончания семестра и исключения видны, но кнопка добавления в них недоступна.
4. Выбрать день, затем готовую лекцию/семинар. Лекция из одной группы охватывает весь явно заданный набор; семинар — только выбранную строку группы. Преподаватель и группы подставляются из назначения. Аудиторию, время и повторение выбирает сотрудник.
5. Если назначения нет, ссылка в форме открывает настройку и возвращает в выбранный слот с черновиком правила в URL. Данные черновика повторно валидируются; URL не даёт полномочий и не содержит секретов. По возвращении выбрать готовое занятие и заново проверить план.
6. Перед публикацией видны дисциплина, преподаватель, группы, время, конкретные даты и исключения. Сервер проверяет занятость во всём вузе; конфликт называет ресурс, дату и занятый интервал. Ввод сохраняется. Подтверждение требуется отдельно; частичной публикации нет.
7. После сохранения показано число занятий и группы, новые записи выделены. Можно добавить следующий слот с новым operationId. Опубликованную пару редактируют «на одну пару» либо «с даты для будущих повторений» через существующий редактор.

В новом семестре дата начала остаётся произвольной. Для недели начала по умолчанию предлагается числитель, можно выбрать знаменатель: опорный понедельник вычисляется, прежняя модель parity не заменяется. Сохранённая опора не пересчитывается автоматически. Каникулы/исключения не сдвигают чередование. Переход по типу недели показывает настоящие диапазоны дат и не меняет повторение занятия.

## Данные и совместимость

Additive migration `20261117190000_teaching_assignments` добавляет:

- `TeachingAssignment`: universityId, programId, subjectId, kind LECTURE/SEMINAR, active, version.
- `TeachingAssignmentGroup`: assignmentId, universityId, groupId, teacherId, active. Одна строка группы в настройке; у лекции сервер требует одного преподавателя во всех строках.

Назначение не связано с конкретным семестром. Subject, Faculty → Program → StudentGroup, Teacher/TeacherSubject переиспользуются. Набор групп явный: новая группа не включается сама. Можно хранить независимые назначения, не создавая копию Subject. Неактивные ресурсы и отсутствующая связь преподавателя с дисциплиной объясняются в каталоге; новые размещения с ними запрещены сервером. Выключение настройки не удаляет историю.

Изменение назначения влияет только на новые размещения. В ScheduleTemplate/segments и ScheduleEntry остаются опубликованные снимки групп/ресурсов/подписей. Команда размещения проверяет версию выбранного назначения; аудит публикации сохраняет снимок правила и групп. Старые занятия не используют каталог как динамический источник данных. Прежние текстовые занятия не сопоставляются автоматически. Оценки и студенческий доступ по активной группе не меняются.

**Для установки понадобится полный согласованный выпуск с миграцией**, а не app-only пакет PR #63. Код app-only обновления, зависимости и package-lock.json в этой задаче не менялись. Это не разрешение на выпуск или deploy.

## API и права

Существующий защищённый `GET /api/staff/schedule/builder` дополнен `assignments` — минимальными настройками своего вуза, без учётных записей/студентов/секретов. Предел — 500 настроек; превышение явно даёт 413.

Через прежний `POST /api/staff/schedule/builder` с preview/commit:

- `ASSIGNMENT_CREATE(operationId, programId, subjectId, kind, groups[{groupId,teacherId}])`.
- `ASSIGNMENT_EDIT(id, version, active, programId, subjectId, kind, groups[...])`. Идентичность дисциплины/направления/вида при редактировании не меняется, набор групп и преподаватели меняются явно. Не более 50 групп, без дублей.
- `TEMPLATE_CREATE` может содержать `assignment:{id,version,groupId?}`. Для лекции правило обязано содержать весь набор групп и её преподавателя; для семинара — одну выбранную группу и её преподавателя. Прежние команды без назначения сохранены для совместимости, не получают дополнительных прав.

Авторизация STAFF, same-origin/JSON, Zod, предел тела, текущие rate limits, университетский advisory lock и аудит сохранены. Проверки связей, активности, версий и глобальных конфликтов повторяются под блокировкой при commit. Token привязан также к состоянию справочников/структуры: изменение назначения, связей или ресурсов требует нового предпросмотра. Ошибка аудита откатывает настройку и строки групп. Повтор operationId отвергается, конкурентный stale edit не создаёт второй результат.

Runtime-политика новых таблиц — SELECT/INSERT/UPDATE, без DELETE/DDL/TRUNCATE; негативные проверки расширены. Backup/restore сравнение дополнено новыми таблицами. Шифрование, подпись, security gates не ослаблены.

## Проверки и оставшаяся ручная приёмка

Unit покрывают каталог, доступность ссылок, явный набор групп, A/B, неполные недели, начало в выходной, исключения и переход года. PostgreSQL integration покрывают publication snapshots, конфликтующую конкуренцию, stale preview, STAFF/CSRF/вузовскую область, связи преподавателей и rollback при отказе аудита. Новый E2E проходит от STAFF-настройки до настоящего просмотра двух STUDENT: одна общая лекция, разные семинары, исключения и конфликт аудитории; повторное использование в следующем семестре и новая неназначенная группа. Отдельный E2E проверяет создание семестра со знаменателя через UI.

Точные результаты всех локальных и удалённых проверок — в Draft PR и отчёте. Исторические результаты #41 не являются результатами этой ветки. Независимая проверка человеком без подсказок, реальные телефоны/клавиатуры и полный WCAG/screenreader остаются ручными условиями. Наличие скриншотов не доказывает прохождение такого пользовательского исследования.

## Связь с успеваемостью — уточнение 18.11.2026

Новый раздел Issue #62 реализован в том же PR #65: основной STAFF-путь теперь требует группу до выбора студента. Subject из настройки расписания появляется в той же форме результата, без новой дисциплины и без обязательного опубликованного занятия. При смене группы сбрасываются студент/новый результат/курсоры. Под membership/university lock CREATE повторно проверяет groupId и актуальное прикрепление, поэтому поддельный студент из другой группы и форма до перевода не записывают результат. Личная история и явные исправления сохраняются через отдельный режим истории. [Контракт успеваемости](GRADES.md), [живые кадры и сквозная матрица](screenshots/issue-62/grade-link/README.md).
