# Внутренние уведомления студента

Источник: [Issue #48](https://github.com/bam-low/mgimo/issues/48), Q1–Q8 утверждены владельцем 14.11.2026 в рекомендованном варианте. Реализация находится в отдельной feature-ветке от main `131b3675`; до ручного merge Draft PR не считать её принятой в main. Production **NO-GO**.

## События и права

Только STUDENT in-app. Решение EnrollmentRequest APPROVED/REJECTED, Application TAKE/COMPLETE/REJECT и замена готовой справки создают сообщения. COMPLETE справки даёт одно «Демонстрационная справка готова» вместо двух сообщений. Черновые загрузки/замены, комментарии, создание собственной заявки, перевод/отзыв и неуспешные операции не уведомляют. При COMPLETE событие сохраняет ссылку на текущий документ для предупреждения о последующей версии; прежний механизм выдачи файлов не меняется.

Получатель — UniversityMembership источника. Перевод сохраняет историю и readAt. Активный STUDENT без учебного доступа (PENDING/REJECTED/после отзыва или деактивации структуры) видит собственные общие шаблоны/даты/прочтение, но не содержание заявки, ответ, причину отказа, documentId или ссылку на закрытую заявку. Список и count используют тот же membership predicate. Отключённые User/University, неверная роль, неоднозначный контекст и отозванная сессия закрывают раздел.

Решение прикрепления ведёт в кабинет, если относится к последнему запросу; для прежнего запроса ссылка не подменяется новым запросом. Заявка открывается только при текущем studentAccess, а карточка и скачивание независимо авторизуются на каждом новом HTTP-запросе. Уведомление не является capability. Старое сообщение о справке предупреждает о новой версии; студент получает только текущий разрешённый файл.

## Хранение и транзакции

Аддитивная миграция `20261114123000_notifications`: Notification, составные FK владельца/вуза/источника, sourceKey UNIQUE, CHECK типов и времени, индекс непрочитанных; существующие таблицы получают необходимые UNIQUE-индексы. Старые события **не заполняются**. До отдельного решения нет TTL, пользовательского удаления, архива, backfill и сброса прочтения.

Доменное изменение, ApplicationEvent/история прикрепления, Notification и AuditLog создаются одной транзакцией. Источник приложения — существующий event UUID, прикрепления — `enrollment:<requestId>:decision`. Дубли не подавляются безусловным catch: доменные guards/version/unique сохраняют безопасный отказ и откат. Ошибка уведомления/аудита откатывает всё действие. Уже сохранённая отдельным upload черновая версия не удаляется при неудавшемся последующем COMPLETE.

Отметка прочтения блокирует membership, проверяет действующую сессию и текущего получателя, затем блокирует scoped Notification. Первое readAt и один NOTIFICATION_READ сохраняются атомарно. Повтор возвращает прежнее readAt без нового аудита. readAt не сбрасывается при переводе/отзыве/восстановлении. NOTIFICATION_CREATED дополняет исходный доменный аудит, не заменяя его.

Runtime получает SELECT/INSERT Notification и только **колоночный UPDATE(readAt)**. UPDATE других полей, DELETE и DDL запрещены. Триггер разрешает единственный переход NULL → время, запрещает изменение происхождения и обратное прочтение. Точный privilege checker проверяет единственное допустимое column ACL, исходник новой trigger-функции, триггеры и отсутствие EXECUTE/GRANT OPTION. Остальные таблицы и их ограничения не ослабляются.

## API

- GET `/api/notifications?filter=all|unread&cursor=...` — 25 записей, стабильный порядок createdAt/id и scoped cursor. Даже прочитанный anchor остаётся допустимым для пагинации непрочитанных; чужой anchor даёт 404, некорректный синтаксис возвращает первую страницу как текущий pagination contract.
- GET `/api/notifications/unread-count` — собственные непрочитанные.
- GET `/api/notifications/:id` — общая карточка и актуальная доступность target; GET никогда не меняет readAt.
- POST `/api/notifications/:id/read`, JSON `{}` — идемпотентное прочтение. Запрещены переданные membershipId/readAt/source/неизвестные поля.

Все ответы private/no-store; строгий Zod, current actor, server ownership и university scope; для POST — sameOrigin/существующий JSON body limit. Чужая запись/cursor404, сессия401, роль/неактивность403; сохраняются415/413/429/503 и безопасная диагностика. Идентификатор файла, raw event payload, ответ или текст заявки в DTO уведомления не попадают. href строится только сервером из внутренних маршрутов.

Новые отдельные HMAC rate keys: чтения120/мин на membership и240/мин на проверенный source, read-write 60/мин и120/мин соответственно. Production auth/application/upload limits не меняются, E2E buckets не сбрасываются. Серверные страницы используют те же scoped read-функции; API ограничивает частоту своих запросов.

## Интерфейс

Компактная кнопка в шапке, прежние пять нижних пунктов и верхний «Выйти» сохранены. Счётчик приходит из авторизованной серверной загрузки, обновляется при новом серверном рендере/ручном обновлении и успешном прочтении; нет polling/SSE/push/внешних каналов. Если count недоступен, остаётся рабочая ссылка с понятным доступным именем.

Страница `/notifications`, фильтры, пагинация и `/notifications/:id`; при возврате сохраняются filter/cursor. Простое открытие списка ничего не читает. Явное открытие карточки пользователем после показа запускает отдельный POST read; prefetch отключён, GET не пишет. Из списка доступна явная кнопка; нет массового прочтения/возврата в непрочитанное. Ошибка POST сохраняет карточку и кнопку повтора; повтор после потери ответа безопасен.

Пустое/всё прочитано/ошибка/нет доступа/старый источник/новая версия — настоящие состояния. Academic Editorial 2.0, русские шаблоны, ширины 360/390/768/1280, клавиатура, метки/не только цвет. [Скриншоты](screenshots/issue-48/README.md). STAFF уведомления, настройки каналов, backfill, реальный deploy и production GO отсутствуют.

## Проверки и воспроизведение

[LOCAL_DEMO](LOCAL_DEMO.md): чистая локальная PostgreSQL, migrate/seed, STUDENT и STAFF. Студент2 создаёт демонстрационную справку → сотрудник принимает/загружает образец/выполняет → студент открывает уведомление и скачивает. После замены готового документа появляется отдельное сообщение. Сотрудник отзывает прикрепление → уведомление общее доступно, API заявки/файла403; после разрешённой повторной подачи и одобрения доступ возвращается, readAt сохраняется.

Unit проверяет матрицу; PostgreSQL integration — настоящие доменные транзакции, отказ Notification/AuditLog и откат, конкурентные решения/read, FK/immutability, IDOR/cursor/count, перевод/отзыв/revoked session. Playwright выполняет обе роли/реальные bytes/concurrent TAKE/read/CSRF/revoke/recovery и четыре ширины во всех runtime. Restore closed VPS сравнивает все строки Notification/readAt/ownership, проверяет уникальность повторной первопричины, исходные файлы и аудит. Точные результаты и CI — в Draft PR после фактического завершения; перечень тестов здесь не является заявлением о зелёном CI.


Проверка длинной staff-очереди: E2E находит точную карточку через настоящую пагинацию, в том числе на второй странице. Первоначальный timeout по ссылке был получен до полной готовности streamed DOM; после синхронизации загрузки обычный клик прошёл. Отдельный дефект интерфейса не подтверждён, общий staff UI не менялся. Для прочтения дополнительно обрывается ответ после настоящего серверного200: карточка/ошибка сохраняются, повтор получает прежнее readAt без второй доменной записи.
