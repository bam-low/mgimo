## Реализованная техническая конфигурация для ревью

IMPLEMENTED, Codex, 2026-11-04, разрешённый scope Issue #15: Node 24/Next 16 сохранены; версии зависимостей и команды — README/lockfile. TTL 8ч/updateAge 30м/freshAge 15м; штатный scrypt, origin checks/nonce CSP/no-store, PostgreSQL rate counters. Это выбранные технические значения для ревью владельцем, не прежние утверждённые продуктовые числа. Частичные уникальные индексы и audit immutable trigger реализованы миграцией. Предложения P09/P10 ниже сохраняют историю; реализованное подмножество описано в Architecture/миграции, остальные детали future остаются открытыми.

IMPLEMENTED, Codex, 2026-11-05, [ревью PR #16](https://github.com/bam-low/mgimo/pull/16#pullrequestreview-5776005065): site-wide/email-only отказ заменён лимитами доверенного источника и пары источник+email; logout не зависит от лимита входа. Нет неявного доверия X-Forwarded-For: публичный запуск требует ingress overwrite/изоляции и платформенной anti-abuse защиты (конкретная реализация OPEN, deploy вне scope). RateBucket получает expiry/index и bounded concurrent cleanup, включая legacy RateLimit; maintenance-команда для простоя. Технические детали и остаточные риски — README/Architecture. Это устранение замечаний текущего scope, не новое продуктовое решение.

IMPLEMENTED для ревью, Codex, 05.11.2026: отдельный @vercel/next ABI2 → Build Output API3 материализатор с официальным download, чистая сборка с canaries, webpack module graph/NFT/package/file/runtime gates; без Vercel CLI в зависимостях. Исходный standalone gate сохранён. Это техническая подготовка A38, не принятие расширения для публичного запуска. Параметры pg pool/direct migrations/daily cron, ограничения и [ручные launch gates](DEPLOYMENT.md) описаны отдельно. Synthetic identity/credentials утверждены Issue #20 (A40) и реализованы для ревью; Render fallback остаётся PROPOSED. Cloud/РФ/ingress gates не объявляются закрытыми.

IMPLEMENTED для ревью, 05.11.2026, Issue #20: source-bound HMAC ticket (10min/30s clock skew) использует User.email unique как replay barrier без новой сущности/миграции. Credentials выдаются только после общей транзакции, повторно не возвращаются, не сохраняются plaintext на сервере/в browser storage; по [UX-ревью владельца PR #21](https://github.com/bam-low/mgimo/pull/21#issuecomment-6663570795) hidden лишь выключает reveal уже выданного пароля и сохраняет реквизиты в памяти открытой страницы до возврата/приватного сохранения. Явное завершение (переход ко входу)/navigation/refresh/pagehide очищают их. Pending fetch при hidden/pagehide/unmount отменяется отдельно, поздний ответ не раскрывает пароль. Это техническое исполнение A40, не новый auth/session framework. Три независимых seed пароля проверяются, не сбрасываются; новая явно начатая попытка расходует source quota. Остальные launch gates A38 сохраняются.
