# Учебное рабочее пространство сотрудника

Согласованный объём: [Issue #70](https://github.com/bam-low/mgimo/issues/70).
Текущий визуальный стиль сохраняется. Изменения действующего VPS и очистка его данных в эту задачу не входят.

## Структура

Курс — необязательное положительное целое поле `StudentGroup.course`, а не свойство направления. Одно направление объединяет группы разных курсов. Прежние строки получают `NULL`; интерфейс показывает «Курс не указан». Заполнить курс можно в редакторе группы.

Факультет → направление → группа отображаются с отдельными отступами. Архивирование сохраняет историю и закрывает доступ вложенной ветке. Подтверждаемое физическое удаление доступно только без зависимостей, включая неактивные связи и прежние прикрепления. Сервер проверяет вуз, роль, версию и зависимости в транзакции под университетской блокировкой. FK остаются последней защитой при конкурентном появлении связи. Аудит создания и удаления не удаляется.

Runtime получает DELETE только для Faculty, Program и StudentGroup. Удаление учебной истории, оценок, обращений, файлов, уведомлений и аудита по-прежнему запрещено. После миграций полный сценарий установки должен применить и проверить обновлённую политику роли.

## Расписание

`/staff/schedule` — единый рабочий экран. Сверху раскрывается настройка календаря семестра: произвольное название, даты, тип первой неполной недели, опорный понедельник и исключения. Без явного выбора настроенного семестра публикация недоступна. Внутри страницы доступны преподаватели и аудитории.

Фильтры: семестр → факультет → направление → курс → группа. «Все курсы» сохраняет обзор направления; «Курс не указан» помогает обработать старые группы. Фильтр не разделяет общую лекцию: предпросмотр всегда перечисляет все участвующие группы, включая другой курс.

Свободная ячейка подставляет группу, дату и время. В форме можно раскрыть существующий редактор закреплений, создать дисциплину и настроить общую лекцию либо отдельные семинары. Это тот же справочник Subject и TeachingAssignment, без параллельных сущностей. После сохранения выбирается готовое занятие. Для публикации обязательны преподаватель и аудитория; сервер проверяет оба ресурса.

Разовое размещение выбрано по умолчанию. Доступны еженедельное повторение, числитель и знаменатель. Публикации предшествует серверный предпросмотр конкретных дат, групп, количества и конфликтов по всему вузу; подтверждение повторно проверяет план. Для серии доступны «Только эту» и «Эту и последующие». Сохраняются ограничения изменения ручных будущих занятий из [SEMESTERS.md](SEMESTERS.md).

Прежний редактор доступен отдельно: `/staff/schedule/manual`, «Демо · ручное расписание». Исторические занятия не преобразуются автоматически. Существующие адреса конструктора, семестров и справочников сохраняются.

## Отмена и уведомления

Одна отмена изменяет только выбранное занятие и оставляет отметку в расписании. `ScheduleCancellation` сохраняет неизменяемый снимок дисциплины, времени и участвующих групп. Новое уведомление `SCHEDULE_CANCELLED` ссылается на этот снимок. Отмена, доменный аудит, снимок, уведомления и их аудит записываются одной транзакцией.

Получатели — подтверждённые STUDENT с действующим прикреплением к активным затронутым группам на момент отмены. Общая лекция не создаёт повторного уведомления одному membership. Ключ события содержит ID занятия и новую версию; уникальный ключ уведомления включает вуз, membership и источник. Повтор устаревшего запроса получает конфликт версии и не создаёт дублей. Повторная настоящая отмена после восстановления — новое действие с новой версией. При занятой строке получателя операция целиком возвращает 409 для повтора; KEY SHARE / SKIP LOCKED перед записью уведомлений исключает ожидание FK на membership под университетской блокировкой. Прежний строгий FOR UPDATE для перевода, отзыва и оценок сохранён.

После перевода или отзыва собственное уведомление сохраняется. Переход к расписанию доступен только при действующем учебном доступе и прикреплении к одной из исходных групп. Чужие уведомления недоступны. Внешние каналы и polling не добавляются.

## Оценки

Сотрудник выбирает группу, затем студента. Результаты сгруппированы в карточки дисциплин с действием «Добавить оценку». Каждая оценка остаётся самостоятельной записью; исправления и аннулирование сохраняются в аудите.

Обе роли используют одну серверную функцию расчёта за включительный период `from`/`to`. Пустые границы означают всю доступную историю. Среднее — арифметическое по действующим MARK; CREDIT и аннулированные записи исключены. Зачтено/не зачтено подсчитываются отдельно. Значения агрегируются по всему периоду, а не по странице из 25 записей. Это простой средний балл, без весов, рейтинга или GPA. Средний также показан в каждой карточке дисциплины. Карточки доступны для всех дисциплин с результатами за период; переход «Все результаты дисциплины» открывает её собственную историю с пагинацией, без повторения карточек по общей странице результатов.

## Предпросмотр очистки

Подготовьте JSON с точным списком вымышленных записей, например:

```json
[{"kind":"group","id":"ЯВНЫЙ_ID_ПРОВЕРЕННОЙ_ТЕСТОВОЙ_ГРУППЫ"}]
```

В изолированной копии БД, с DATABASE_URL вне Git:

```sh
node scripts/preview-academic-cleanup.mjs --university demo-university --records /private/test-records.json
```

Допустимые виды: faculty, program, group, semester, subject, teacher, room, assignment, lesson, membership, enrollment, enrollmentRequest, application, document, grade, notification, cancellation. Требуется 1–100 явных записей. Вуз обязателен, отсутствующие и чужие ID останавливают весь отчёт без частичного вывода. Транзакция PostgreSQL строго READ ONLY / REPEATABLE READ. Отчёт содержит количества непосредственных FK-зависимостей и аудита; содержимое обращений, файлов, персональных полей и секреты не выводятся. Косвенные зависимости не обходятся автоматически; их нужно явно включить в следующий список.

Инструмент не содержит режима удаления. Пометка возможности удаления — результат предварительного просмотра, а не разрешение или гарантия: сервер повторно проверяет состояние при отдельном действии. Очистка VPS требует отдельного решения владельца, сверки полного списка и резервной копии. Этот PR не подключается к действующему VPS.

## Миграции и совместимость

- `20261118160000_group_course`: nullable course и SQL CHECK положительного курса. Старые строки не меняются.
- `20261118163000_schedule_cancellation`: неизменяемые снимки отмен, nullable ссылка уведомления и расширение строгих SQL-проверок источника. Прежние уведомления остаются неизменными.

Изменяются схема и политика runtime-роли: требуется полный сценарий обновления, а не app-only пакет. Утверждённые миграции перечислены с checksum в существующем release-контракте. Репетиция должна отдельно доказать сохранность старых строк при добавлении nullable-полей, новые пустые таблицы на старой БД и точный ledger. Большой экспорт запускается отдельно владельцем. Production NO-GO сохраняется.
